# contributing

small prs welcome. bug fixes, docs, tests and focused features all count.

## what you need

- a Mac on macOS 14 or newer (the deployment target is 14.0)
- Xcode 16 or newer
- no Apple developer account. local builds are ad-hoc signed

the app is Swift and SwiftUI with some AppKit. dependencies come in through Swift Package Manager, pinned
to exact versions in `PromptAnnotator.xcodeproj`:

| package | version | used for |
|---|---|---|
| WhisperKit (`argmaxinc/argmax-oss-swift`) | 1.1.1 | on-device speech to text |
| Sparkle | 2.10.0 | auto-updates on release builds |

the project is `PromptAnnotator.xcodeproj`, scheme `PromptAnnotator`. that's the old internal name. the app
ships as "da transcribuh".

## build and run

```sh
git clone https://github.com/bicrick/da-transcribuh.git
cd da-transcribuh
xcodebuild -project PromptAnnotator.xcodeproj -scheme PromptAnnotator \
  -configuration Debug -derivedDataPath build \
  CODE_SIGN_IDENTITY=- build
open "build/Build/Products/Debug/da transcribuh.app"
```

the first build resolves the packages, so it takes a while. in Xcode, open the project, set signing to
"sign to run locally", pick the `PromptAnnotator` scheme and hit run.

first launch walks you through permissions (microphone, accessibility, screen recording). macOS ties those
grants to the signature, so an ad-hoc rebuild can make it ask again. that's expected.

the first recording downloads the default speech model (`small.en`, about 217 MB) into Application Support.
after that everything runs offline.

`scripts/install-dev.sh` is Patrick's script for a Developer ID signed dev install. you don't need it.

## test

```sh
xcodebuild test -project PromptAnnotator.xcodeproj -scheme PromptAnnotator \
  -derivedDataPath build CODE_SIGN_IDENTITY=-
```

tests live in `PromptAnnotatorTests/`, one file per area (`AlignerTests`, `SessionClipboardTests`,
`HotkeyChordTests`, ...). if you change behavior, add or update a test next to the closest existing one.
run the suite before you open a pr.

## where things are

see [docs/architecture.md](docs/architecture.md) for the module map and how a take flows from the hotkey
to the paste. short version:

- `PromptAnnotator/SessionController.swift` runs a session
- `Speech/` is transcription (WhisperKit, or your own OpenAI-compatible server)
- `Capture/` is the mic, screen grabs and markup
- `Export/` turns a take into the collage, transcript and clipboard paste
- `Settings/` is the settings window

## code style

- match the file you're in. there's no linter config, so consistency with the surrounding code is the rule
- small types with one job. `enum` namespaces for stateless helpers (`Aligner`, `ContactSheet`)
- UI state lives on `@MainActor`. heavy work (decode, PNG encode, disk writes) stays off it
- comments say why, not what. short `///` doc comments on types and anything non-obvious
- user-facing text is plain and short. the app name is always lowercase: da transcribuh
- no new dependencies without talking about it in an issue first

## pr flow

1. for anything bigger than a small fix, open an issue first so we can agree on the approach
2. branch off `main`. names like `fix/paste-delay` or `docs/architecture` are fine
3. keep it small. one thing per pr
4. build and run the tests locally
5. open the pr and fill in the template. ui change? drop a before/after screenshot
6. Patrick reviews and merges. expect questions, not silence

things to leave alone unless the pr is about them:

- release signing (`Config/Release.xcconfig`, `scripts/release.sh`, `scripts/make-appcast.sh`). that's for
  shipping builds, see [docs/releasing.md](docs/releasing.md)
- version numbers (`MARKETING_VERSION`, `CURRENT_PROJECT_VERSION`). they get bumped at release time
- readme images. they're generated by `docs/readme/render.py` (needs playwright + pillow). rerun it, don't
  hand edit the pngs

## where to start

- issues labeled `good first issue`
- docs that don't match what the app does
- tests for code in `Support/` and `Export/` that has thin coverage
- bugs you hit yourself. a clear repro with your macOS version and Mac model is a great first contribution
